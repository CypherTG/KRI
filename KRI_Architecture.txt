List 4: KRI_Automations

Stores automation configuration for each client. Power Automate checks this list to know when to send greetings, reminders, and follow-up messages.

Column NameColumn TypeRequiredDescription / NotesTitle (Automation Name)Single line of textYesShort label for the automation rule
ClientIDLookupYesLookup to KRI_Clients — which client this rule applies to
AutomationTypeChoiceYesBirthday Message / Holiday Greeting / Follow-Up Reminder / Seasonal Card
TriggerDateDate and TimeNoSpecific date for one-time automations or reminders
IsRecurringYes/NoYesIf Yes, automation repeats annually (e.g. birthday, Christmas)
IsEnabledYes/NoYesToggle to disable without deleting the rule
MessageTemplateMultiple lines of textNoCustom message content or notes for personalisation
LastSentDateDate and TimeNoAuto-updated by Power Automate when a message is sent
AssignedToPerson or GroupNoKCC member responsible for this client's automations
Power Automate scheduled flows query this list daily, filtering for IsEnabled = Yes and TriggerDate = Today. The LastSentDate column prevents duplicate sends — the flow checks it before sending.

List 6: KRI_StageHistory

An audit trail of every KRI stage change for every client. Automatically written by Power Automate whenever the KRIStage field on KRI_Clients changes.

Column NameColumn TypeRequiredDescription / NotesTitle (Change Summary)Single line of textYesAuto-generated, e.g. 'Acme Corp: K ? R'
ClientIDLookupYesLookup to KRI_Clients — the client whose stage changed
PreviousStageChoiceYesThe stage before the change: Knowledge / Rapport / Intimacy
NewStageChoiceYesThe stage after the change: Knowledge / Rapport / Intimacy
ChangedByPerson or GroupYesThe KCC team member who made the change
ChangedDateDate and TimeYesDate and time the stage was updated
NotesMultiple lines of textNoOptional reason or context for the stage change
This list is written to by Power Automate only — never directly by users. A trigger flow fires whenever KRIStage is modified in KRI_Clients, capturing the old and new values automatically.

2. Intricate Implementation Plan
As the lists are already made and saved on SharePoint, we will bypass the actual list creation steps and focus directly on configuring operations, mapping the advanced automation logic, and structuring the Power Apps Canvas application.
Phase 1: Validating Lookups and Permissions
? Verify ClientID Lookups: Navigate to KRI_Communications, KRI_Engagements, KRI_Automations, and KRI_StageHistory. Validate that the ClientID column pulls from the ‘Title (Client Full Name)’ field of KRI_Clients. Ensure you retrieve additional fields like Email, JobTitle, Gender, and ProjectName directly through the lookup setting to reduce heavy API load in your Power App.
? Indexed Columns: Go to List Settings for KRI_Clients. Set KRIStage, LastContactDate, BirthdayDate, Gender, and ProjectName as Indexed Columns. This is a safety measure to ensure queries and flows operate smoothly when your lists exceed the 5,000-item threshold.
Phase 2: Power Automate Deep Configuration
? Flow 1: Stage Change Logic: * Trigger: "When an item or a file is modified" on KRI_Clients.
? Add the SharePoint action: "Get changes for an item or a file (properties only)".
? Insert a condition to check if Has Changed: KRIStage is equal to true.
? If true, proceed to trigger a "Create item" action in KRI_StageHistory to log the transition.

? Flow 2: Daily Scheduled Reminders & Birthday Messages:
? Trigger: Recurrence (1 Day frequency, at 08:00 AM).
? Action: "Get items" from KRI_Clients.
? Intricate Logic: Since OData can't filter pure MM-dd dates efficiently from a DateTime column, pull active items and use a Power Automate "Filter Array" matching formatDateTime(item()?['BirthdayDate'], 'MM-dd') to formatDateTime(utcNow(), 'MM-dd'). For all matching profiles, send the Outlook email and trigger an update setting LastContactDate to utcNow().

Phase 3: Power Apps Canvas App Orchestration
? Dynamic Data Connections: Map all 6 active SharePoint lists into your app sources.
? The Master-Detail Client Thread Screen: In Power Apps, drop a vertical gallery bound to KRI_Clients. Display client names using the FirstName and LastName columns directly (e.g. Concatenate(ThisItem.FirstName, " ", ThisItem.LastName)) for a cleaner UX. You can also surface JobTitle, Gender, and ProjectName on each client card for quick context. When a user selects a client from this gallery, populate a second gallery displaying logged communications via the formula: Filter(KRI_Communications, ClientID.Value = SelectedClient.Title). This forms an instantly updating interaction history thread without creating complex parent-child structures.

? Pipeline Management Without Leaderboard: Use standard categorized galleries to represent your KRI_Engagements by their Status choices (Draft, Submitted, Won, Lost). To calculate top metrics on an individual's dashboard, call sums or averages like: Sum(Filter(KRI_Engagements, Status.Value = "Won"), ActualValue).

Phase 4: Final Deployment & Embedding

? After building the screens, save and publish your Power Apps Canvas App.

? On your target modern SharePoint page, put the page into Edit mode.

? Click the + icon to add a new web part and select Power Apps.

? Paste your App link or App ID into the property menu to integrate the platform directly onto your team site.
